# STM32F103 模拟 BiSS-C 位置传感器初步可行性分析与实施计划

## 1. 目标与范围

目标是使用 STM32F103 模拟一个点对点 BiSS-C 位置传感器：接收 iC-MB4 输出的 MA 时钟，在 SL 上返回预先准备的固定数据帧，从而将真实 AMG2000 传感器从系统中替换出来，验证以下链路：

```text
STM32F429 -> SPI -> iC-MB4 -> MA/SL物理层 -> 模拟传感器
```

第一阶段只实现 Single-Cycle Sensor Data (SCD)，不实现从机寄存器访问、EDS、多从机级联和命令处理。模拟位置暂定为 `9500000`，位于当前 CAS 节点 2 的有效范围 `9259537..9769376` 内。

## 2. 已阅读资料

- `BiSS_C_protocol_C6en(1).pdf`：BiSS-C 帧、ACK/START/CDS、数据顺序、CRC、STOP、Timeout 和时序范围。
- `IC-MB4 规格书.pdf`：iC-MB4 SPI 命令、MA/SL 时序、FREQS/FREQAGS、SCD 配置、状态寄存器和 RS-422 条件。
- `MB4AN3_appnote_A2en.pdf`：初始化、AGS、状态诊断、BREAK/INIT、CRC 关闭方法。
- `MB4_AN4_appnote_A1en.pdf`：2 MHz/10 kHz/RS-422/CRC6 的官方配置示例。
- `MB4_factsheet_rev2-1.pdf`：接口能力、速率范围和物理接口概览。
- `MB4_1SL_dllmanual_A3en.pdf`：Windows 评估 DLL；对从机固件没有直接实现价值，但可作为主机参数命名参考。

## 3. 当前 F429/iC-MB4 配置结论

当前 `HARDWARE/SPI/spi.c` 与 AN4 示例基本一致：

| 项目 | 当前值 | 含义 |
| --- | ---: | --- |
| `CFGCH1` (`0xED`) | `0x01` | 通道 1 使用 BiSS-C |
| `CFGIF`/`CLKENI` (`0xF5`) | `0x09` | RS-422，使用内部 20 MHz 时钟 |
| `FREQS` (`0xE6`) | `0x04` | MA = 20 MHz / 10 = 2 MHz |
| `FREQAGS` (`0xE8`) | `0x63` | 自动采样约 10 kHz |
| `ENSCD1/SCDLEN1` (`0xC0`) | `0x61` | 启用从机 1，接收 34 位 |
| `SCRCLEN1` (`0xC1`) | `0x00` | iC-MB4 不执行 CRC 校验 |

当前 34 位的含义是：

```text
26位位置 + 2位状态 + 原传感器6位CRC（作为普通数据接收）
```

这符合规格书关于“关闭 CRC 校验时，应将从机实际 CRC 长度加入 SCDLEN”的要求。因此第一阶段模拟器可以发送任意 6 位 CRC 占位值，但仍必须发送这 6 个时钟位。

此前状态 `EOT=0、SVALID1=0、nAGSERR=0` 表示 iC-MB4 没有完成有效 SCD 帧，故障发生在位置范围过滤之前。模拟从机非常适合作为当前问题的 A/B 隔离工具。

## 4. 协议时序要求

最简点对点单从机帧按 MA 上升沿计数：

| 上升沿序号 | SL 动作 |
| ---: | --- |
| 1 | LAT，同步/锁存位置，SL 保持 Idle 高 |
| 2 | ACK，SL 拉低 |
| 3 | START，SL 拉高（最小处理时间路径） |
| 4 | CDS，第一阶段固定为 0 |
| 5..38 | 34 位 SCD，MSB first |
| 39 | STOP，SL 拉低 |
| 停钟后 | 保持低电平，Timeout 到期后 SL 拉高回 Idle |

BiSS-C 的关键约束：

- 从机在 MA 上升沿生成/更新 SL，主机随后采样。
- MA 允许频率范围覆盖当前 2 MHz。
- 单周期数据处理时间上限为 40 us。
- 标准静态 Timeout 为 12.5..40 us。
- STOP 必须为低，Timeout 到期必须产生 SL 低到高的握手边沿。
- 数据与 CRC 都是 MSB first；CRC 校验位发送前取反。

在当前 2 MHz 下，39 个 MA 周期约为 `19.5 us`。10 kHz 周期为 `100 us`，因此一帧加 15..20 us Timeout 后仍有足够的重新装载时间。

## 5. 可行性结论

结论：**有条件可行，推荐实施。**

STM32F103C8T6 以 72 MHz 工作时，每个 2 MHz MA 周期只有 36 个 CPU 时钟，因此逐边沿 EXTI 中断加 HAL GPIO 写入不可靠。使用定时器输入捕获产生 DMA 请求、DMA 直接写 GPIO `BSRR`，可以把逐位响应延迟和抖动降到硬件级，资源与带宽均满足要求。

推荐优先级：

1. **TIM 输入捕获 + DMA -> GPIO BSRR**：主方案，按位对齐，能自然处理 39 个非整字节时钟。
2. SPI 从机 + DMA：备选；BiSS 帧没有 NSS 且总时钟数不是 8 的整数倍，帧重同步更复杂。
3. EXTI 逐位中断：仅适合低频临时验证，不作为 2 MHz 最终方案。
4. FPGA/CPLD：时序裕量最大，但对此次固定帧诊断属于过度投入。

## 6. 推荐硬件结构

```text
iC-MB4 MA+/MA- -> RS-422接收器 -> F103 TIMx_CHy
F103 SL GPIO   -> RS-422驱动器 -> iC-MB4 SL+/SL-
```

要求：

- 不得把差分 MA/SL 直接接 STM32 GPIO。
- MA 接收端和 SL 接收端分别按链路拓扑配置约 100..120 ohm 终端匹配。
- 确认 MA+/MA-、SL+/SL- 极性；极性错误会表现为 Idle、ACK 和 Timeout 全部反相。
- 确认收发器逻辑侧电平与 STM32F103 引脚兼容；优先使用 3.3 V 逻辑兼容器件。
- iC-MB4 内置 RS-422 仅适用于支持该接口的封装，并要求 4.5..5.5 V 供电；需结合现有原理图确认。
- 建议共地，并用示波器同时观察差分 MA、差分 SL 和 F103 逻辑侧信号。

## 7. F103 固件架构

### 7.1 数据帧

第一阶段固定生成：

```text
position = 9500000 (26 bit)
status   = 0b11（暂按 nE/nW 均正常，最终以实测 AMG2000 位序确认）
crc      = 任意6位占位（MB4 CRC校验关闭）
```

34 位 SCD 组合形式：

```c
scd34 = ((uint64_t)position << 8) | ((uint64_t)status << 6) | crc6;
```

这与当前 F429 的解析方式一致：`SCDATA1[33:8]` 对应 26 位位置，低 8 位对应 2 位状态和 6 位 CRC。

### 7.2 MA 边沿响应

- MA 逻辑信号接到支持输入捕获 DMA 的定时器通道。
- 定时器捕获 MA 上升沿，每个捕获事件产生一次 DMA 请求。
- DMA 源缓冲区为 39 个 32 位 `GPIOx->BSRR` 写值。
- 缓冲区依次表示 LAT、ACK、START、CDS、34 位 SCD、STOP。
- DMA 正常模式传输完成后，SL 已处于 STOP 低电平。

### 7.3 Timeout 与重装载

- DMA 完成中断只启动一个 15..20 us 的单次定时器，不在中断中逐位操作。
- Timeout 定时器到期后将 SL 拉高，恢复 Idle。
- 清除定时器/DMA状态，重装 `CNDTR=39`，准备下一帧。
- 上电后 SL 先保持高电平；开始测试前让主机执行 BREAK，并留出至少 40 us 总线复位时间。
- 增加异常看门狗：若 MA 帧中途停止、DMA 未完成，应在 40 us 内恢复 SL 高并重新装载状态机。

### 7.4 实现约束

- 边沿路径使用寄存器或 LL，不在实时路径调用 HAL GPIO、printf 或动态计算 CRC。
- 帧缓冲区在启动前预计算；运行中只切换预制缓冲区。
- DMA、定时器和 UART 调试中断优先级分离，避免 Timeout 延迟超过 40 us。
- 记录帧计数、DMA完成计数、异常恢复计数，但只在低速后台打印。

## 8. 分阶段实施计划

### Phase 0：基线与接口确认

- 确认 STM32F103 具体型号、系统时钟、可用定时器通道、DMA 映射和 MA/SL 引脚。
- 确认 RS-422 接收器/驱动器型号、方向、供电、终端电阻和差分极性。
- 保存当前 F429 配置和失败日志作为基线。
- F429 的 `0xF4` 操作统一使用驱动已有的 `mb4_write_instruction()`/SPI `WriteInstruction(0x07)` 快速命令，减少主机侧操作歧义。

完成标准：示波器确认 MA 逻辑侧与差分侧同相，SL Idle 为高。

### Phase 1：低速握手验证

- 临时将 F429 MA 降到 250 kHz，例如 `FREQS=0x13`。
- 将自动周期降到约 1 kHz，例如 `FREQAGS=0x9F`，避免低速帧超过 100 us 后与下一次请求冲突。
- F103 先只实现 LAT、ACK、START、STOP 和 15..20 us Timeout。
- 用逻辑分析仪确认第二个 MA 上升沿后 ACK 拉低，START、STOP 和 Timeout 边沿顺序正确。

完成标准：iC-MB4 不再持续报告无法启动帧；波形边沿数与协议表一致。

### Phase 2：固定 34 位数据，CRC 校验关闭

- 加入固定位置 `9500000`、状态 `0b11` 和 6 位占位 CRC。
- 保持 F429 `C0=0x61、C1=0x00`。
- 读取并记录 `F0、F1、F8` 和 `SCDATA1[0..4]`。
- 验证 `EOT=1、nAGSERR=1、nSCDERR=1、SVALID1=1`。
- 验证 F429 解出的传感器值为 `9500000`，且不会被节点 2 范围过滤。

完成标准：连续至少 `10^6` 帧无错位、无无效帧。

### Phase 3：逐级提速

- 250 kHz/1 kHz 稳定后升到 1 MHz，再升到当前 2 MHz。
- 最后恢复 `FREQAGS=0x63`，达到 10 kHz。
- 每档记录 ACK 延迟、SL 建立时间、Timeout、错误计数和 DMA 异常计数。

完成标准：2 MHz/10 kHz 下连续运行，固定位置不跳变，iC-MB4 状态无错误。

### Phase 4：启用标准 CRC6

- 根据 BiSS-C 规则实现多项式 `x^6 + x + 1`（完整表示 `0x43`）、起始值 0、MSB first、发送结果取反。
- CRC 输入覆盖 `26 位位置 + 2 位状态`，不包含 ACK/START/CDS/STOP。
- 修正 F429 的 CRC 启用分支：28 位非 CRC 数据应配置 `SCDLEN1=27`，即 `C0=0x5B`，并设置 `C1=0x06`。
- 先用离线测试向量核对，再打开 iC-MB4 CRC 校验。

完成标准：CRC 开启后 `SVALID1` 持续有效；主动翻转一个 CRC 位时，`SVALID1` 能按预期清零。

### Phase 5：故障注入与原传感器对比

- 分别注入：无 ACK、START 延迟过长、错误帧长、错误 CRC、Timeout 不回高、SL 极性反转。
- 建立每种故障与 `F0/F1/F8` 状态位的对应表。
- 用相同线缆和主机配置切回 AMG2000，对比 MA/SL 波形。

完成标准：能够明确判断真实故障属于传感器本体、RS-422 链路、iC-MB4 配置还是 F429 上层处理。

## 9. 当前代码需要同步处理的事项

- CRC 开启分支在写 `0xC0` 前没有明确给 `txData[0]` 赋正确值；启用 CRC 前必须修复。
- 当前驱动提供专用 `mb4_write_instruction()`，建议对 `F4` 的 AGS/BREAK/INSTR 操作统一使用该接口。
- 调试期间避免高频 BREAK/重启 AGS；既有记录表明频繁软复位可能使 AMG2000 进入必须掉电恢复的异常状态。
- 第一阶段固定位置必须位于当前节点范围内，否则会出现“底层帧成功、上层仍统计无效”的假象。
- `EOT` 表示 SCD 数据阶段结束，不包含从机 Timeout；不能用 EOT 替代 SL Timeout 波形检查。

## 10. 主要风险与缓解措施

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| DMA 写 SL 延迟过大 | ACK/数据采样错位 | 先低速验证；使用 BSRR、最高 GPIO 速度、寄存器级配置；示波器量化延迟 |
| 帧起点丢失 | 所有位整体偏移 | 上电先装载 DMA；增加 40 us 无边沿恢复状态机 |
| Timeout 不正确 | 下一帧无法启动、nAGSERR | 独立单次定时器生成 15..20 us Timeout，并检查 SL 上升沿 |
| RS-422 极性或终端错误 | Idle/ACK 反相或振铃 | 差分双通道测量、核对 A/B 标号、在接收端终端匹配 |
| CRC 位序不确定 | SVALID1 始终无效 | 第一阶段关闭硬件 CRC；随后用抓包和故障注入核对标准 CRC |
| 低速测试周期冲突 | 前帧未完下一帧已启动 | 降 MA 时同步降低 FREQAGS，或使用 AGSMIN/外部触发 |
| F103 资源映射冲突 | DMA 无法由目标通道触发 | 在选定具体 F103 工程后按参考手册确认 TIMx_CHy/DMA 通道 |

## 11. 预期判定结果

模拟器成功且真实传感器失败：优先检查 AMG2000、传感器供电、传感器模式、线缆和 SL 驱动。

模拟器也失败且无 ACK：优先检查 MA/SL 极性、RS-422 接口、iC-MB4 通道和电气连接。

模拟器有 ACK 但 SVALID 无效：优先检查 START/CDS 位序、34 位长度和 CRC 配置。

模拟器 SCDATA 正确但应用统计无效：检查节点号、位置有效范围和 F429 数据解析。
